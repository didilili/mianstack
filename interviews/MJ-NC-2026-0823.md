## 原帖正文

> 1. 请先简单做一下自我介绍。
>
> 2. 你简历里的 AI 经历比较多，但计算机基础相关内容较少。你对计算机基础知识的了解怎么样？
>
> 3. 你是否有前后端两方面的开发经历，包括 JavaScript、Vue 等语言和框架的使用？
>
> 4. 你简历里提到了基于 SSE 和 Event Trace 的 Agent 可视化工作台，能介绍一下 SSE 吗？
>
> 5. 为什么 Event Trace 选择 SSE？是因为只需要单向推送，不需要双向交互吗？
>
> 6. 除了单向、双向通信的区别，SSE 和 WebSocket 还有哪些区别？
>
> 7. 实习时研究的代码知识图谱，整体是用什么结构组织的？
>
> 8. 你刚才介绍的这部分，是否就是你在代码知识图谱方向主要负责的工作？
>
> 9. 你做的更多是基于知识图谱的上层应用能力，那么你对知识图谱本身的底层原理了解多少？
>
> 10. 知识图谱存成一张图时，底层使用什么数据结构？读取这张图时如何遍历？
>
> 11. 你的个人项目是否使用了 MyBatis、MySQL 和 REST API？MySQL 主要存储哪些数据？
>
> 12. 能讲一下 MySQL 的事务隔离吗？
>
> 13. 事务隔离有哪些级别？
>
> 14. RR 和 RC 最主要的区别是什么？
>
> 15. 能举一个你在项目中真实创建索引的例子吗？
>
> 16. 你的订单表大概是什么量级，有多少条数据？
>
> 17. 为什么用“订单号 + 购买者 ID”建立联合索引？
>
> 18. 选一个你投入比较多，或者收获比较大的实习项目，详细介绍一下。
>
> 19. 在这个多智能体平台中，你负责的是其中一部分，对吗？具体职责边界是什么？
>
> 20. 什么情况下应该抽象成一个专业 Agent，什么情况下只需要一个 Skill？你如何区分和判断？
>
> 21. 你说 Agent 应该自主判断、决策，但实际又使用固定的 Workflow 编排，没有完全采用 ReAct 等自主决策模式，这是怎么考虑的？
>
> 22. 是否希望整个流程的骨架与功能点固定下来？
>
> 23. 整个多 Agent 编排，包括编排引擎，是你们自己实现的吗？
>
> 24. 多 Agent 之间如果出现调度冲突、输出冲突或者其他异常，你们会怎么处理？
>
> 25. 听起来目前主要是失败通知和中断恢复，是否也有自动修复能力？
>
> 26. 这些不同场景下的冲突处理、失败处理链路，具体是怎么实现的？是提前通过 Workflow 编排好的，还是部分交给大模型判断，只在关键节点做约束？
>
> 27. 是否可以理解为 Agent 内部自主决策，而主 Agent 到各子 Agent 的流程由人为编排？
>
> 28. 以“测试环境拉不起来”为例，重试三次、失败后存储信息并通知研发，这条链路是固定的 Skill 吗？
>
> 29. 是否是把部署环境、失败信息入队等能力拆成多个 Skill，再自行编排起来？
>
> 30. 既有 Agent 之间的相互调用，又有每个 Agent 内部的多步骤执行，你们如何评估 Agent 本身的稳定性？
>
> 31. 你刚才讲的是如何验证 Agent“可用”，但可用不代表稳定。你们如何评估多次执行结果的稳定性？准确率大概维持在什么水平？
>
> 32. 你们是否做过整体、系统性的 Agent 效果评测？还是主要依赖不同的人去尝试？
>
> 33. 有没有遇到过模型幻觉，例如需求识别不准确、执行偏离预期？你们怎么规避？
>
> 34. 如果把传统电商从搜索商品到下单的全流程改造成通过与 Agent 交互完成，你会怎样设计整体架构？
>
> 35. 用什么业务指标衡量这个 Agent 的效果？
>
> 36. 你的方案是一个主 Agent 配合若干功能，还是拆成多个 Agent？是否可以概括为“单 Agent + 多 Skill”？
>
> 37. 研发平台和电商下单都是相对固定的流程，为什么前者使用多 Agent，后者使用单 Agent？这两种结构的划分依据是什么？
>
> 38. 你用“前后端可以并行”解释多 Agent 的必要性，但单 Agent 调用多个 Skill 也能实现并行。那为什么仍然需要多 Agent？
>
> 39. 是否可以理解为：研发平台整体由主 Agent 集中协调，但各子 Agent 又能独立运行、单独承接任务？
>
