## 原帖正文

> [#发面经攒人品#](https://www.nowcoder.com/creation/subject/c121d108a0d94e04b8821f14c3acadd5) 时间:7.22 45min，今天想起来记一下面经，有的地方可能忘了，凑合看吧
> 整体就是围着简历项目、后端基础和 Agent 场景问的
> 项目拷打，问得很细：
> 1. 项目里的 Skill 上线后，有没有可量化的指标？
> 2. 项目 QPS 是多少？如果请求量涨 10 倍，哪些模块需要优化？
> 3. 我答了 Prompt 每次都要 RPC 查数据库，可以先考虑加缓存。然后被追问缓存怎么设计、过期时间怎么定。
> 4. 如果重新设计这个系统，你觉得还有哪些地方能优化？
> 5. 上线后接口耗时突然变高，怎么排查？
> 6. 某个 Skill 的 Prompt 配置有问题，怎么快速修复并止损？
> 7. 一个大 Prompt 被拆成多个 Skill，除了省 Token，还有什么收益？
> 
> 缓存、数据库、MQ 这一块也问了不少：
> 1. 缓存失效后大量请求同时打到数据库，会发生什么，怎么解决？
> 2. 缓存和数据库数据不一致，怎么保证最终是新的？
> 3. MQ 突然积压几十条消息，怎么分析原因？
> 4. 两个请求同时更新同一条记录会怎样？
> 5. 我答会加行锁阻塞另一个事务，然后继续追问：如果没有行锁怎么办？
> 6. 数据库里有哪些索引？
> 
> 还有一点基础网络：
> 1. HTTP 请求从发起到返回，大概经历哪些阶段？
> 2. HTTP 和 RPC 的区别是什么？
> 
> Agent 相关：
> 1. Agent 和普通 LLM 的区别？
> 2. 为什么需要 MCP？
> 3. 一个 Agent 怎么连接多个 MCP？
> 4. 设计一个旅游 Agent，你会怎么写 Prompt？
> 5. Memory 怎么设计？
> 6. Agent 连续调 5 个工具，第二或第三个失败，恢复机制怎么做？
> 手撕是无重复字符的最长子串，滑动窗口。
> 
> 整体感觉面试官不是为了问倒你，更多是顺着你的回答继续深挖。所以简历里的每一条真的都得准备好，尤其是缓存、数据库、Agent 工具调用、异常恢复这些。写了就一定会问。 [#我的秋招第一次#](https://www.nowcoder.com/creation/subject/bf41e545f33d45549b6bc337ac77b226)
