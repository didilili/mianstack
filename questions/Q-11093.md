> 在面栈阅读：[LangGraph 的节点、边和状态如何定义并组成可执行图？](https://mianstack.com/question/q-11093)

## 核心回答

`LangGraph` 用 **`State` 承载数据、Node 执行逻辑、Edge 决定下一步**，再把这些定义编译成可运行的图。

开发时先声明状态字段及更新规则，再注册节点。节点读取当前状态，返回本节点修改的字段；普通边连接固定步骤，条件边根据更新后的状态选择分支或退出。最后调用 `compile()` 得到可执行对象，用 `invoke()` 取最终结果，或用 `stream()` 观察中间更新。

例如问答流程可以拆成“规范问题 → 检索 → 检查资料 → 回答”。资料不足且仍有预算时回到检索；资料足够时生成答案。循环次数和结束条件都放在控制逻辑中，而不是仅提醒模型不要死循环。

## 定义一张可执行图

下面用不调用模型的简化例子说明接口：第一轮检索没有资料，第二轮取得资料，最多检索两轮。实际项目中用真实检索与生成实现替换两个节点即可。

```python
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    question: str
    attempts: int
    docs: list[str]
    answer: str

def retrieve(state: State):
    attempt = state["attempts"] + 1
    docs = ["可回看的资料"] if attempt >= 2 else []
    return {"attempts": attempt, "docs": docs}

def route(state: State):
    if state["docs"]:
        return "answer"
    return "retrieve" if state["attempts"] < 2 else "stop"

def answer(state: State):
    return {"answer": "依据资料回答：" + state["question"]}

def stop(state: State):
    return {"answer": "资料不足"}

builder = StateGraph(State)
builder.add_node("retrieve", retrieve)
builder.add_node("answer", answer)
builder.add_node("stop", stop)
builder.add_edge(START, "retrieve")
builder.add_conditional_edges("retrieve", route, {
    "retrieve": "retrieve", "answer": "answer", "stop": "stop"
})
builder.add_edge("answer", END)
builder.add_edge("stop", END)
graph = builder.compile()
result = graph.invoke({
    "question": "如何配置设备？", "attempts": 0,
    "docs": [], "answer": ""
}, config={"recursion_limit": 10})
```

`compile()` 负责检查并组装图结构和运行时，不会提前执行检索，也不意味着把 `Python` 编译成机器码。这里节点返回的是局部更新，未修改的 `question` 继续保留。

## State 怎样合并？

无 `Reducer` 的字段默认由新值覆盖，例如本轮 `docs` 替换上轮结果。需要累积多个分支的证据时，可以给字段声明追加或按文档 ID 去重的 `Reducer`。消息历史常用 `add_messages`，它支持按消息 ID 追加或更新，不能等同于简单列表拼接。

如果并行节点都更新同一个默认覆盖字段，运行时无法判断应该采用哪一个值，可能报并发更新错误。应分别写独立字段，或定义能正确归并的 `Reducer`；还应考虑去重、顺序与重放，不能只是把并行写入当作修改全局字典。

## 图在运行时怎样推进？

`LangGraph` 的 `Pregel` 运行时把节点调度为 Actor，通过 Channel 传播数据。每个 super-step 先确定可执行节点，再执行，随后统一应用该步更新；同一步中的并行节点不会直接读取彼此尚未提交的更新。

`recursion_limit` 约束图的 super-step 数，不是 `Python` 递归深度，也不等于工具调用次数。示例中的 `attempts` 才是业务检索轮次。需要暂停恢复时，编译阶段接入 `Checkpointer`，并在调用配置中传入 `thread_id`；需要跨进程保存时，应选择持久化后端。

## 常见追问

**节点一定是 Agent 吗？**

不一定。普通函数、检索、格式校验、模型调用或完整子图都可以成为节点。拆分依据是职责和状态边界，不是每个节点都要用一次模型。

**条件边和普通边能随意一起加吗？**

同一节点配置多条出路，可能导致多条路径一起触发。若本意是互斥选择，应明确采用条件路由；不要在已有固定后继的情况下再加一条条件边，并误认为后者会覆盖前者。
