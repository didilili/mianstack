> 在面栈阅读：[了解或使用过哪些现有 Agent 产品？](https://mianstack.com/question/q-0544)

## 核心回答

我会按任务理解现有 Agent 产品：`Coze`（扣子）偏项目中的人和 Agent 协作，可通过技能、工具及插件扩展任务；`Dify` 提供可视化工作流来组织模型、文件处理、变量和条件分支；`OpenClaw` 偏自托管的消息入口与 Agent 网关，把会话、工具和自动化能力接到日常沟通渠道。

下面以 `Dify` 把产品说明整理成多平台文案为假设使用示例。我会配置输入、平台参数提取与无效输入分支，再读取参考文件、整合事实，按平台生成文案并格式化输出；检查时回看节点变量、日志和原材料，确认分支正确、事实没有被扩写。

## 展开说明

### 这些产品的着重点有什么不同？

| 产品       | 本题关注的能力                       | 观察重点                                     |
| ---------- | ------------------------------------ | -------------------------------------------- |
| `Coze`     | 项目、Agent协作及技能/工具扩展       | 背景与文件如何进入任务，结果怎样持续修改     |
| `Dify`     | 工作流节点、变量、文件输入和条件分支 | 固定流程是否清楚，错误能否定位到具体节点     |
| `OpenClaw` | 自托管网关、消息通道、会话和工具     | 消息如何路由，任务状态与外部执行结果如何核对 |

产品不等同于底层模型。模型决定生成和推理能力，产品还需要提供工具、状态、交互和执行环境。也不是每个可视化流程都由模型自主规划：有些任务是预先编排的工作流，只有部分节点需要动态决策。

### 一次 Dify 任务怎样从输入走到产物？

1. 在 `User Input` 节点收集草稿、参考文件、目标平台、语气和语言。把字段设为下游可引用变量，而不是每个节点重新粘贴材料。
2. 用 `Parameter Extractor` 把“X 和 LinkedIn”等输入规范为平台数组，再用 `IF/ELSE` 检查提取结果；没有有效平台时，直接由 `Output` 返回输入提示，不继续生成。
3. 有效分支通过 `List Operator` 区分图片与文档；文档先经 `Doc Extractor` 转成文本。`LLM` 节点再整合草稿、文档文本及支持视觉时的图片，提取主题、事实和必要细节，要求依据用户提供的材料。
4. 用 `Iteration` 遍历目标平台，分别生成风格要求和文案，返回平台名与正文等结构化字段；再经 `Template` 排成按平台分节的文本，由 `Output` 返回。产物是一组可审阅文案，不代表已经发布到平台。

验收时分别试正常输入、无效平台和含参考文档的输入，核对分支、变量和节点 `Last Run` 日志；逐项回查产品能力、日期和数字是否有材料依据，再看语言与格式是否符合要求。若旧版本说明被混入，先核对文件提取和整合节点实际拿到了什么，修正材料或规则后重新测试，不能仅让模型改得更肯定。

### 怎样评价产品，而不是只报名字？

优先看任务能否完成、证据是否可检查、失败是否可恢复、数据与权限是否适合自己的场景。支持插件并不自动代表已接通某个企业系统；自托管也不等于自动获得全部数据或不存在安全风险。具体能力要看所用版本和配置。

## 可能的追问

### OpenClaw 和普通聊天工具有什么区别？

它用网关连接消息渠道与Agent执行能力，管理会话、路由及工具，使对话能推进实际任务。关键差别在执行链路与状态，而不只是模型回答更长；能否访问文件或执行某个操作，仍取决于配置与工具权限。

### 只看过文档，还没深度用过，怎样回答？

直接讲清已经了解的产品定位，再深入一条确实研究过的能力与实现。若有实际试用，就补上那次任务的输入、过程和产物；无需把列举的全部产品写成自己都已熟练使用。
