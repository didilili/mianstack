> 在面栈阅读：[深分页使用游标后如何支持任意页跳转？](https://mianstack.com/question/q-0835)

## 核心回答

普通游标只知道“从上一条记录继续”，不能直接知道第十万页从哪里开始。任意跳页需要额外的位置索引、预计算页锚点或结果快照；若没有这些信息，只能付出跳过前面记录的代价。把 `OFFSET` 换成 `WHERE id > ...`，却不知道对应的 `id`，并没有解决任意跳页。

先根据产品需要选方案：连续浏览用游标；浅层精确跳页可以保留偏移分页；高频深层跳页则用带成本的锚点或物化结果。不能承诺既任意跳页、结果实时不变，又始终是固定低成本。

## 游标本身怎样保持稳定

例如按 `created_at DESC, id DESC` 排序，下一页使用上一页末条的两个值：

```sql
SELECT id, created_at, amount
FROM seller_bill
WHERE seller_id = :seller
  AND (created_at < :last_time
       OR (created_at = :last_time AND id < :last_id))
ORDER BY created_at DESC, id DESC
LIMIT :page_size;
```

需要匹配的索引如 `(seller_id, created_at, id)`。唯一的 `id` 打破相同时间的并列关系；不能把页码乘以页大小得到的行序号，直接当作存在且连续的业务 `ID`。

## 支持任意定位的几种方式

- **稀疏锚点**：缓存某些页起始位置，跳页时找最近锚点，再扫描剩余距离。锚点必须绑定筛选条件、排序和结果版本；数据变化后需要失效或重建。
- **结果快照**：先物化符合条件的有序 `ID` 列表或分段位置，再按页读取。适合账单、报表等需要稳定结果的场景，代价是生成、存储与有效期管理。
- **浅分页或受控偏移**：限定时间范围和最大页码，必要时先从覆盖索引取出当页 `ID` 再读取详情。这可减少宽行回表，但扫描大量偏移记录的成本仍存在。

只记录创建时间上界，未必冻结状态变化、删除和排序字段更新。要求翻页期间完全一致时，需要明确的快照或版本语义，而不是仅把时间戳编码进游标。
