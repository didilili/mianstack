> 在面栈阅读：[Skill 是什么，怎样帮助 Agent 完成具体任务？](https://mianstack.com/question/q-18402)

## 核心回答

Skill 是把一类任务的**执行方法、约束和配套资源**封装成可复用技能包，供 Agent 在相关任务中加载。它通常以 `SKILL.md` 为入口，描述何时使用、先做什么、怎样处理异常和交付什么；还可以附带参考文档、模板或脚本。

它帮助 Agent 完成任务的过程是：宿主先提供技能名称和简短描述，模型判断当前任务是否适用；命中后读取具体步骤，再按需取用资料并调用工具，最后检查结果。例如处理月度销售报表，技能固定销售额口径、缺字段处理和报告格式，文件工具负责读表，程序负责计算，模型负责解释异常与组织报告。

Skill 的收益是复用已整理的方法，减少每次重新说明规则和加载无关资料。执行效果仍依赖模型、数据和工具；写了一份技能文件，并不会自动增加数据库权限或改变模型权重。

## 从技能文件到任务结果

可以把执行链拆成四个职责明确的阶段。

1. **发现与选择。** 宿主扫描或注册技能，将 `name`、`description` 和读取位置交给 Agent。描述要指出任务对象、动作和适用条件，否则相近技能容易误选。用户显式指定也是一些宿主支持的入口。
2. **加载方法。** Agent 读取所选 `SKILL.md`，获得输入要求、处理步骤、输出约定和失败分支。不同产品可以采用不同加载接口，不能假定都存在 `load_skill()`。
3. **取得资料并执行。** 只加载本次分支需要的口径、示例或模板；适合精确计算的部分直接执行脚本。脚本源码可以不送给模型，但参数和执行结果仍可能占上下文。
4. **核对结果。** 既看最终产物，也看关键中间条件：统计范围是否正确，源数据是否缺项，报告中的结论能否对应计算结果。发现问题后调整技能或工具，再回放相关任务。

以报表任务为例，输入是订单明细和月份；技能要求先排除取消订单、按约定区分退款时间，再计算销售与退款，最后生成报告。若明细缺少退款日期，进入补充条件分支，而不是生成一个看起来完整的趋势。

## 与 Prompt、工具和 Agent 怎样分工？

- 当前 Prompt 给出本次需求，例如“分析十月份门店报表”。
- Skill 保存此类需求的处理方法，例如指标口径、处理顺序与报告模板。
- 工具完成具体操作，例如读取工作簿、执行计算、导出文件；工具可以由本地函数、命令行或 `MCP` 服务提供。
- Agent 结合任务、技能和工具结果决定下一步，并处理过程中的异常。

一个纯写作技能也可以只包含说明与参考资料；一个复杂技能也可能组合多个工具。技能文件里的流程是供 Agent 遵循的指令，若要求某一步绝不跳过或某个操作绝不越权，还要在程序、权限和状态控制中落实。

## 怎样判断它确实帮上了忙？

分别检查“是否选对”和“选对后是否做好”。用应触发、相近但不适用、缺少输入和工具失败等任务，对照有无技能或新旧版本，比较任务正确性、关键步骤、产物质量与成本。只看文件结构正确，不能证明技能有效。
