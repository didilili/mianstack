> 在面栈阅读：[实现带超时时间和超时次数限制的 Promise 重试。](https://mianstack.com/question/q-0146)

## 核心回答

每次尝试都调用任务工厂，创建新的 `Promise`，让它与超时 `Promise` 竞争；超时就累计次数并按约定决定是否重试，成功或退出时清理计时器。不能反复等待同一个已经创建的 `Promise`，那不会重新发起任务。

题干没有说明“超时次数”是不是总重试次数。下面约定 `maxTimeouts` 表示允许出现的超时总数：设为三，第三次超时立即失败；普通业务错误直接抛出。若面试官要求“最多重试三次”，应另设 `maxRetries`，首次尝试不计入重试数。

## JavaScript 实现

任务工厂接收每次独立的 `AbortSignal`。定时器先决定超时结果，再请求取消底层任务；只有本次计时器触发的超时才计入预算。

```javascript
class TimeoutError extends Error {
  constructor() {
    super("attempt timed out");
    this.name = "TimeoutError";
  }
}
async function retryTimeout(factory, { timeoutMs, maxTimeouts }) {
  if (
    typeof factory !== "function" ||
    !Number.isFinite(timeoutMs) ||
    timeoutMs < 0 ||
    !Number.isInteger(maxTimeouts) ||
    maxTimeouts < 1
  ) {
    throw new TypeError("invalid factory or timeout options");
  }
  let timeoutCount = 0;
  while (true) {
    const controller = new AbortController();
    let timer;
    let timedOut = false;
    try {
      const timeout = new Promise((_, reject) => {
        timer = setTimeout(() => {
          timedOut = true;
          const error = new TimeoutError();
          reject(error);
          controller.abort(error);
        }, timeoutMs);
      });
      const task = Promise.resolve().then(() => factory(controller.signal));
      return await Promise.race([task, timeout]);
    } catch (error) {
      if (!timedOut || !(error instanceof TimeoutError)) throw error;
      timeoutCount++;
      if (timeoutCount >= maxTimeouts) throw error;
    } finally {
      clearTimeout(timer);
    }
  }
}
```

## 怎样使用与理解取消

```javascript
const result = await retryTimeout(
  (signal) =>
    fetch("/api/report", { signal }).then((r) => {
      if (!r.ok) throw new Error(`HTTP ${r.status}`);
      return r.json();
    }),
  { timeoutMs: 3000, maxTimeouts: 3 }
);
```

把 `r.json()` 包进工厂返回的链，超时才覆盖读取和解析响应，而不只覆盖收到响应头之前的等待。平台或SDK可能另有超时和取消配置，需核对它们覆盖的是连接、完整响应还是整次任务。

`Promise.race()` 本身只选择最先完成者，不会终止其他任务。`abort()` 也是协作式取消：工厂忽略信号时，旧尝试仍可能在后台继续，下一次重试就可能与它重叠；服务端收到请求后是否停止也不能由客户端保证。带写入副作用的重试要复用业务幂等标识，必要时先查询原操作状态。

真实远程调用通常还需总截止时间、退避与抖动，并区分可以重试的网络错误和不可重试的业务错误。题目只约定超时重试，不能把所有异常都无条件重试。
