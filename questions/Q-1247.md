> 在面栈阅读：[MCP 与 Skill 有什么区别？](https://mianstack.com/question/q-1247)

## 核心回答

**MCP 是 AI 应用接入外部能力的协议；Skill 是 Agent 可复用、按需加载的任务能力包。**这里的 Skill 指 Agent Skills 这类组织任务知识和流程的方式，不局限于某一个产品。

MCP 约定客户端和服务端怎样发现能力、传递参数、读取资源和返回结果，常见能力包括 Tools、Resources 和 Prompts。Skill 则说明什么时候处理某类任务、按什么步骤做、参考哪些资料、交付什么结果；采用 Agent Skills 格式时，通常以 `SKILL.md` 为入口，也可以附带脚本、模板和参考文件。

例如做代码审查，Skill 规定先理解需求和差异，再检查正确性、安全和边界条件，最后按位置和依据输出问题；Agent 可以通过 MCP 工具读取仓库差异、提交记录或测试信息。**Skill 提供任务方法，MCP 提供标准化接入，两者可以组合。**只用本地文件、CLI 或直接 API 的 Skill 也能工作；接入 MCP 的 Agent 也不必依赖 Skill。

## 展开说明

### 1. 两者标准化的对象不同

MCP 面向客户端与服务端的交互。Host 是承载模型调用的 AI 应用，内部的 Client 与 Server 交换协议消息，Server 再连接真实工具或数据源。统一的能力描述和消息约定，有助于同一服务被多个支持协议的应用复用。

Skill 面向一类任务的知识与执行方法。`name`、`description` 帮助宿主发现适用任务，`SKILL.md` 正文给出流程、输入输出和特殊情况，额外文件承载脚本、资料或模板。宿主通常先了解元信息，任务需要时再加载正文和资源，这就是渐进式披露。

Skill 不一定只有提示词，也可以带可执行脚本；但脚本仍由宿主的执行工具或运行环境调用。把脚本放进技能目录，并不会自动获得数据库连接、网络访问或文件权限。具体能力还取决于宿主、依赖和授权配置。

### 2. 怎样把 Skill 与 MCP 接到同一次任务里

以代码审查为例，一条组合链路可以是：

1. Agent 根据用户任务找到代码审查 Skill，读取检查流程和输出要求。
2. 发现需要差异和相关代码时，选择已接入的仓库查询工具，由宿主通过 MCP Client 调用相应 Server。
3. Server 返回差异、文件内容等结果，Agent 按 Skill 的方法继续分析，必要时补查。
4. Agent 输出问题位置、依据和建议，实际读写范围仍由宿主与服务端控制。

Skill 负责说明“这类任务怎样完成”，MCP 不替 Agent 决定审查是否充分；MCP 连接成功，也不代表工具返回的信息足够或结论正确。是否完成任务，要按 Skill 的交付要求和业务验收检查。

### 3. 不要按“本地文件”和“远程服务”划界

MCP Server 可以在本机运行，也可以部署为远程服务。Skill 可以由本地目录提供，也可以通过支持的服务分发，位置不是两者的本质区别。

当前官方已有 **MCP Skills 扩展**，可以借助 Resources 分发 Skill 文件；它规定的是传输映射，技能目录、元信息和渐进式披露仍遵循 Agent Skills 格式。该扩展面向 `2026-07-28` 及之后的基线协议，实际能否使用还取决于客户端和服务端是否支持。因此，“通过 MCP 取得一个 Skill”并不改变它们在协议与任务内容上的职责。

### 4. 如何判断需求该落在哪一层

如果要让多个 AI 应用复用同一组仓库、工单或数据查询能力，重点是统一能力接入，可以考虑 MCP。如果已有工具可用，只是某类任务总要重复解释检查顺序、业务规则和输出模板，适合沉淀为 Skill。如果两类需求同时存在，就组合使用。

MCP 的 Prompts 本身也能提供可复用指令，所以不能说“MCP 只有代码、Skill 只有文字”。Skill 的特点是用能力包组织任务说明及附带文件；MCP 的特点是标准化能力发现和交互。业务规则写进 Skill 有助于指导模型，真正的参数校验、数据权限和操作限制仍应由执行层落实。

## 常见追问

### Skill 会替代 MCP 吗？

一般不会，因为解决的问题不同。Skill 可以教 Agent 调用直接 API、CLI 或 MCP 工具；MCP 可以提供 Skill 所需的数据与动作，也可以通过扩展分发 Skill。本质上是任务方法和能力接入的组合。

### 一个 Skill 能调用多个 MCP Server 吗？

可以描述跨多个服务的流程。例如先读取代码仓库，再查询关联工单，最后汇总审查结论。宿主需要已接入相应服务，并给当前任务合适的权限；Skill 中写了工具名称，不代表它自动存在或已经获准使用。

### 按需加载是不是就完全不占上下文？

不是。元信息会有开销，激活后正文和读取的资料也会占用上下文。渐进式披露减少的是一开始加载全部详细规则的负担，效果取决于元信息规模、触发准确性和实际读取内容，不能简单推导为固定的 Token 节省比例。
