> 在面栈阅读：[进程、线程和协程有什么区别？](https://mianstack.com/question/q-0292)

## 核心回答

**进程侧重资源与隔离，线程是进程内的执行流，协程是由程序或运行时组织的可挂起、可恢复任务。** 三者主要从资源边界、调度方式和使用场景区分：

- **进程**：通常有独立虚拟地址空间，持有文件、权限等资源，进程之间通过管道、Socket、共享内存等方式通信。隔离性较强，适合独立服务或需要隔离的计算任务。
- **线程**：同一进程内共享堆、代码和打开的文件等资源，各自保存栈、寄存器等执行现场。内核线程由操作系统调度，可以在多核上并行；共享数据时需要同步，避免竞态。
- **协程**：在一个或多个线程上由语言运行时或库调度，等待合适的 I/O 操作时可挂起，让承载线程执行其他任务。它通常比为每个请求建立一个系统线程更轻，适合大量等待网络、模型或数据库响应的场景；具体调度和并行能力取决于实现。

以 `Python` `asyncio` 为例，同一事件循环一次执行一个任务，任务真正等待尚未完成的异步操作时，循环可推进其他任务。这能提高 I/O 并发承载能力，但不会让同一线程上的多段 CPU 计算同时运行。

先看资源归谁，再看执行怎样切换：进程有各自的地址空间，线程共享进程资源但保留自己的执行状态；底部用 `Python` `asyncio` 展示任务 A 等待 I/O 时，事件循环如何推进任务 B。

## 从资源与调度看三者的关系

一个进程中可以有多个线程，一个线程上的事件循环又可以管理多个协程任务。协程并没有绕开线程直接占用 CPU；操作系统仍调度实际承载它们的内核执行单元。

| 比较角度 | 进程                       | 线程                     | 协程／轻量任务                               |
| -------- | -------------------------- | ------------------------ | -------------------------------------------- |
| 资源边界 | 默认独立地址空间，隔离较强 | 同进程共享多数资源       | 通常共享承载进程的资源，不提供进程级隔离     |
| 执行状态 | 包含进程资源与线程执行现场 | 各自有栈、寄存器等现场   | 保存挂起后恢复所需状态，形式依运行时而异     |
| 调度者   | 内核安排进程内的可运行线程 | 内核线程由操作系统调度   | 程序、事件循环或语言运行时                   |
| 通信     | 通常需显式 IPC             | 可读写共享对象，但需同步 | 可用共享对象、队列或消息，也可能存在逻辑竞争 |
| 主要代价 | 创建、隔离与跨进程通信     | 栈、调度与共享数据同步   | 任务状态、运行时调度与非阻塞 I/O 配合        |

跨进程切换可能涉及地址空间与缓存局部性的变化；同一进程内的线程通常不需要更换地址空间；用户态轻量任务切换又可减少部分内核调度工作。但实际成本受运行时、栈、锁竞争、内存和任务数量影响，不能给三者套一个固定的性能倍数。

## 为什么协程适合 I/O 等待？

假设一个研搜服务同时处理网页搜索和模型请求。请求发出后，大量时间可能花在等远端响应。若每个请求都阻塞一个线程，线程数量和栈内存会随等待任务增加；异步客户端则可以让任务挂起，由事件循环在响应到来后继续执行。

这样重叠的是等待时间，并非把所有计算同时放到一个核心上运行。实际仍要限制并发数、连接数和外部接口速率，防止一次创建太多任务耗尽连接或触发限流。

使用协程还需要链路配合：在 `async def` 内直接调用阻塞式网络库、长时间计算或 `time.sleep()`，仍会占住事件循环线程。可以采用异步接口，或把适合的阻塞 I/O 移到线程池；需要多核计算时，再根据运行时选择进程池、线程池或其他并行计算方案。

## 怎样选进程、线程或协程？

**需要强隔离或独立生命周期**时，优先考虑进程。例如独立服务、容易崩溃的第三方处理程序，或适合分片的计算任务。进程池能复用工作进程，但任务和结果的序列化、传输仍有成本。

**已有同步阻塞接口，需要共享进程内数据**时，可以用有边界的线程池承接。例如调用只有同步接口的 I/O 库，同时控制最大并发、超时和共享数据的访问。

**大量可异步等待的 I/O**适合协程。模型流式请求、网络检索、消息消费等可以在等待期间让出执行机会。若真正瓶颈在计算、数据库连接或外部服务限额，增加协程数量并不能自动提高吞吐。

这些方式可以组合：多个服务进程提供隔离与多核承载，每个进程运行事件循环，必要时把阻塞函数交给受控线程池。选择应围绕任务和瓶颈，而不是只追求创建更多执行单元。

## 常见追问

**有 `await` 就一定会切换任务吗？** 不一定。可等待对象如果已经就绪，执行可能直接继续；如果整段代码一直计算，或只等待立即完成的操作，也不能指望它自动给其他任务充分运行机会。`asyncio` 的协作调度依赖真正的挂起点。

**单线程协程还需要考虑并发安全吗？** 需要。一个任务读取共享状态后，在等待期间另一个任务可能修改它，前者恢复后依据旧状态写回，仍会产生逻辑竞争。应缩小共享可变状态，必要时使用适合该运行时的锁或队列；阻塞式线程锁不能随意跨异步等待持有。

**线程一定比协程更差吗？** 不是。线程可以承接同步阻塞库，也可以利用多核执行计算，实际还取决于语言和运行时。以 `CPython` 为例，启用 `GIL` 的常规构建与 `free-threaded` 构建在 `Python` 代码的多线程并行能力上不同；释放 `GIL` 的扩展又有自己的情况，不能把某一种模式的结论推广到所有线程。

**一个线程出错，一定导致整个进程退出吗？** 要看错误类型。未处理的语言级异常可能只终止该线程；非法内存访问等进程级故障则可能导致整个进程退出。共享内存意味着错误也可能破坏其他线程依赖的数据，进程边界通常提供更强隔离。
