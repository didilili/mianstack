> 在面栈阅读：[每日工作计划能力应沉淀为 Skill 还是长期记忆来持久化？](https://mianstack.com/question/q-3325)

## 核心回答

**每日规划的方法应沉淀为 Skill，稳定的用户偏好可进入长期记忆，当天任务与进度则保存为任务状态。** 三者都能持久化，但用途和更新频率不同，不能只按“下次还用不用”来二选一。

- **Skill 保存怎么做**：先读取日程和待办，再处理截止时间、优先级与时间冲突，最后按固定格式输出计划。
- **长期记忆保存对谁做、长期遵循什么**：例如用户时区、常用工作时段；记录适用范围，允许用户修改。
- **任务状态保存今天做到哪**：具体日期的会议、待办、已完成项和待确认事项，应以任务或日历系统为准，也可保存成带日期的计划文件。

每天执行时，先加载规划 Skill，再带入适用偏好和最新任务数据。这样流程可以复用，昨天的待办也不会被误当成今天仍有效的事实。

## 为什么不把每日计划全部放进一个地方？

Skill 适合维护稳定的步骤、工具使用规则和输出模板。例如“先锁定固定会议，再安排有截止时间的任务，剩余时间处理可选项”，可以反复使用；当天有哪些会议则要每次读取。如果把两者写在同一份 Skill 中，每天都要改能力说明，还容易带入过期日程。

长期记忆也不适合堆积每天的完整计划。它更适合少量、长期有用且有适用范围的信息。“我通常上午处理需要专注的工作”可以作为规划偏好；“今天上午有事，全部安排到下午”只影响当天。用户明确更改长期习惯时，再更新对应偏好，避免同时保留互相冲突的版本。

从概念上看，Skill 也可视为一种程序性记忆；工程上把它独立成能力包，是为了按任务加载、维护流程版本和附带资源。**保存了 Skill 只代表流程可复用，定时触发仍由调度机制负责，真实日程的读写仍由工具完成。**

## Hermes Agent（Python）

在 `Hermes Agent` 中，每日规划同样应拆成规划 Skill、通用用户记忆和当天状态。它已有 Skill 按需读取、持久记忆和会话历史能力；每日计划可以利用这些机制组织，无需把一整天的待办都塞进全局记忆。

### 规划步骤与任务专属偏好放在 Skill

例如可以将“读取最新日程和待办、识别固定时间与截止日期、安排任务、输出冲突和待确认项”写入一个每日规划 Skill；只在规划任务使用的排序偏好、模板和任务系统使用说明也放在其中。这里描述的是 Skill 的编排方式，不是一个已内置的日程业务模块。

`Hermes` 先提供技能名称和描述，执行相关任务时通过 `skill_view(name)` 读取完整 `SKILL.md`，需要额外说明时再读取其目录内的参考文件。创建或修正规划方法可使用 `skill_manage` 的 `create`、`patch` 等操作；应按工具返回的状态确认修改是否已经生效。这样修改办理方法与更新当天计划各有入口。[按需加载说明](https://github.com/NousResearch/hermes-agent/blob/81a55437f3f31a9f12a30c53b6c5d49d420898aa/website/docs/user-guide/features/skills.md#L172-L183)、[读取实现](https://github.com/NousResearch/hermes-agent/blob/81a55437f3f31a9f12a30c53b6c5d49d420898aa/tools/skills_tool.py#L592-L615)、[管理入口](https://github.com/NousResearch/hermes-agent/blob/81a55437f3f31a9f12a30c53b6c5d49d420898aa/tools/skill_manager_tool.py#L768-L793)。

### 全局记忆只留跨任务通用的信息

当前实现把记忆保存在所选 profile 的 `memories/` 中：`USER.md` 保存用户档案、偏好与风格，`MEMORY.md` 保存助手笔记、环境事实和通用约定。`memory` 工具支持 `add`、`patch`、`remove`。

这一版本的工具说明还进一步收紧了范围：全局记忆用于不依赖具体任务、每次会话都可能需要的信息。因此，用户时区、通用沟通语言可以进入 `USER.md`；“每日计划只展示三个最重要任务”这类只服务规划工作的偏好，应随对应 Skill 加载。当天待办、完成日志和临时进度不写入这两个全局文件。[记忆工具的范围与目标定义](https://github.com/NousResearch/hermes-agent/blob/81a55437f3f31a9f12a30c53b6c5d49d420898aa/tools/memory_tool.py#L372-L401)。

### 当天状态读最新来源，区分保存与提示更新

一次规划可以按这样的顺序完成：加载规划 Skill，读取当前日程和待办，结合通用用户信息生成当天计划；用户说“第二项已完成”，就更新对应任务或当天计划产物。下次继续规划时，再读取最新状态，而不是从旧偏好或昨天的回答推断任务是否完成。

还要区分记忆文件与模型当前看到的记忆：`load_from_disk()` 在加载时生成提示快照，`format_for_system_prompt()` 返回该快照。**记忆写入存储不会立即重刷提示；上下文压缩后，`invalidate_system_prompt()` 会重新从磁盘加载记忆并清理提示缓存，后续重建时带入更新。** 新会话也会重新加载。因此当轮使用刚改的内容，应依据用户当前指令和工具返回结果，不必等待提示刷新。这是在更新时效与提示前缀复用之间的取舍。[加载与快照实现](https://github.com/NousResearch/hermes-agent/blob/81a55437f3f31a9f12a30c53b6c5d49d420898aa/tools/memory_tool_store.py#L221-L253)、[快照读取](https://github.com/NousResearch/hermes-agent/blob/81a55437f3f31a9f12a30c53b6c5d49d420898aa/tools/memory_tool_store.py#L618-L621)、[压缩后的重新加载](https://github.com/NousResearch/hermes-agent/blob/81a55437f3f31a9f12a30c53b6c5d49d420898aa/agent/system_prompt.py#L814-L832)。
