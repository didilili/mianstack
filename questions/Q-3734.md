> 在面栈阅读：[如何设计高质量 Prompt？如何评估 Prompt 优化是否有效？](https://mianstack.com/question/q-3734)

## 核心回答

高质量 Prompt 要让模型明确**任务目标、必要信息、约束和输出标准**，再根据难点选择示例、步骤拆分或工具。角色用于限定专业视角，不能替代业务信息；格式明确也不代表内容正确。

评估优化是否有效，需要固定模型、样本、检索材料、工具和采样配置，让旧版与新版处理相同任务。按正确性、遗漏、约束遵循、稳定性及成本逐项比较，检查哪些样本改善、哪些退步，再用独立留出集验收。单次回答更流畅、提示词更长，或模型自称“更准确”，都不足以证明优化有效。

## 提示词怎样设计？

1. **定义任务与完成标准。** 例如“从订单文本提取订单号、实付金额与币种”，比“分析订单”更明确；同时规定缺失、冲突和无法判断时的行为。
2. **提供必要上下文。** 说明字段含义、时间范围、业务口径和可用资料。稳定规则与动态输入分开，外部材料保留来源，并清楚标成待处理数据。
3. **写清输出契约。** 指定字段、类型、枚举、缺失值与引用要求。支持原生结构化输出时结合使用，程序继续校验格式和业务语义。
4. **针对难点补示例。** 示例覆盖正常与容易混淆的边界，格式保持一致。简单任务未必需要示例；数量和顺序由实际效果决定。
5. **控制任务复杂度。** 多步流程可以拆为可观察的阶段，计算或精确查询交给工具；需要展示时要求关键依据和检查结果，不依赖一段无法验证的自述推理。

例如把“提取金额”改为：

```text
从订单文本中提取实付金额和币种。
仅依据原文；商品原价、优惠金额不能作为实付金额。
字段缺失时填null，存在互相冲突的实付金额时标记conflict。
输出字段：paid_amount、currency、status、evidence。
输入：{order_text}
```

这段提示新增了对象、判定边界、缺失分支和依据。若后续系统不支持 `null` 或 `conflict`，应先调整输出契约与应用处理，不能只改提示词。

## 优化实验怎样组织？

先把失败分为指令歧义、缺少资料、错误推理、格式不符、工具或流程问题。指令歧义可改写；知识缺失应补充检索；算错金额可以使用计算工具；权限校验需要程序落实。找对失败位置，才能提出有效改动。

随后建立固定基线，开发集用于调整提示，留出集不参与示例选择与调参。每次验证一个主要假设，例如“把实付与原价区别写清楚，是否减少金额混淆”，而不是同时改模型、提示和检索。

| 维度       | 订单抽取示例                       |
| ---------- | ---------------------------------- |
| 正确性     | 金额与币种是否匹配原文             |
| 完整性     | 订单号、金额和币种是否遗漏         |
| 约束遵循   | 缺失是否返回空值，冲突是否正确标记 |
| 稳定性     | 同类输入与重复运行是否持续正确     |
| 成本与延迟 | 输入/输出token、工具调用、总耗时   |

程序能够确定的字段先按规则检查；语义评分给清楚标准，模型裁判需要校准，争议样本回到原文。难例单独观察，不能只看总体平均分。

## 为什么 Prompt 能改变输出，却不能保证正确？

模型按当前上下文生成输出，可表示为 $p_\theta(y\mid x,s)$，其中 $s$ 是提示、$x$ 是任务输入。改提示改变的是生成条件，通常不改变模型参数 $\theta$。它可以使模型更聚焦某种任务、格式和边界，但不能凭空获得不存在的事实，也不能把自然语言规则变成必然执行的程序。

最终应保留带版本的提示、样本、配置与逐条结果；更换模型或关键工具后回放重要任务。如果收益仅存在于少数开发样本，或增加大量成本却未改善目标指标，就继续修改或撤回这次优化。
