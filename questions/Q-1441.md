## 核心回答

RRF（Reciprocal Rank Fusion，倒数排名融合）把多路检索结果按**名次**合成一份排序，不直接相加 BM25 分数与向量相似度。

以向量语义检索和 ES 的 BM25 关键词检索为例：先让两路分别返回有序候选，再按同一片段 ID 对齐。某个片段在一路排名为 `r`，这一路就贡献 `1 / (c + r)`；将它在各路的贡献相加，按总分降序排列。`c` 是平滑常数，名次通常从 1 开始；未进入某路候选的片段，在该路贡献为 0。两路都靠前的片段容易获得较高总分，也能保留只被一路找到的候选。

融合后可以直接取结果，也可以把有限候选交给 Rerank 模型进一步判断内容是否回答了问题。**RRF 解决的是不同排序怎样合并，Rerank 解决的是候选与问题究竟有多相关。**这里用 ES 指代关键词通道；Elasticsearch 本身也支持向量检索，两路可以由同一个引擎完成。

## 为什么用排名，而不是直接加原始分数

BM25 分数受词频、文档长度等影响，向量分数则取决于相似度或距离定义，数值范围和含义不同。例如一路的 8 分和另一路的 0.8 分，不能直接认为前者贡献应是后者的十倍。

RRF 只需要两路各自的名次，因此不用先把原始分数校准到同一尺度。不过，它也舍弃了原分数之间的差距：第一名领先第二名很多，还是只领先一点，RRF 都只看到名次差 1。是否采用 RRF，仍要与单路检索及其他融合方法在实际问题集上比较。

## 用一个例子算清楚

假设返回的都是同一批知识片段的 ID，两路结果如下，左侧排名更靠前：

- 向量检索：A、B、C。
- ES 关键词检索：B、D、A。

取 `c = 60`，不设置额外通道权重，排名从 1 开始：

- B：`1/62 + 1/61 ≈ 0.032522`。
- A：`1/61 + 1/63 ≈ 0.032266`。
- D：`1/62 ≈ 0.016129`。
- C：`1/63 ≈ 0.015873`。

所以融合排序为 **B、A、D、C**。B 在两路分别排第二、第一，累计贡献超过 A；D 虽然没有进入向量候选，也可以通过关键词通道进入合并结果。这里的数字只是排名计算示例，不是相关概率或实际检索效果。

## 实现时怎样把两路接起来

1. **准备可对齐的候选。** 同一知识片段在两路使用一致的 ID，并能取回正文、来源和版本。若一路按整篇文档返回、另一路按片段返回，先确定共同的融合单位，否则不能把两个排名直接相加。
2. **分别完成检索。** 两路使用相符的租户、权限、时间或版本范围，返回各自候选及排名。每路候选数可不同，要给它们足够的覆盖空间，也要考虑检索与后续处理成本。
3. **按 ID 累加贡献。** 同一片段在一条结果列表里只计一次；出现在不同通道时，各贡献一次。保留原通道、原排名和融合分数，便于检查结果为什么排到前面。
4. **排序并控制后续预算。** 融合后按分数取有限候选；需要精排时再交给 Rerank，最后根据证据长度和问题需要选入上下文。片段未被任何通道召回时，RRF 无法把它补回来。

Elasticsearch 的 RRF retriever 可以组合关键词与 kNN 等子检索器。`rank_constant` 对应公式中的平滑常数；`rank_window_size` 控制参与融合的每路候选窗口，最终返回数量又是另一层设置。使用具体版本时，应核对这些参数的约束，不能把它们都叫作同一个 Top-K。

## 常见追问

**调大 c，会让向量检索权重更高吗？**

不会。等权 RRF 的 `c` 同时作用于两路，调整的是单个列表内不同名次的相对差异。`c` 越大，前后名次的贡献越接近。若要偏重某一路，需要显式使用通道权重，例如把其贡献写为 `w / (c + r)`，并评估效果；具体引擎和版本对加权 RRF 的支持不同。

**RRF 后为什么还可能需要 Rerank？**

RRF 没有重新阅读问题和片段，只利用上游名次。候选可能都谈同一个主题，却只有部分满足版本、否定条件或业务限制。Cross-Encoder 等重排模型联合处理问题与候选内容，可以进一步区分这些差异，但会增加推理成本。相关机制可继续看[混合检索的排序融合方式](/question/q-0314/)。

**怎样判断融合有用，而不是增加了噪声？**

把精确编号、专有名词、同义表达和复杂条件等问题分组，在相同数据与上下文预算下比较向量、关键词和融合方案。既看相关证据是否被召回、前排是否更相关，也看最终回答、延迟和成本。若正确片段在合并前就缺失，先查检索与过滤；若已进入候选但被挤出，再查融合和精排。
