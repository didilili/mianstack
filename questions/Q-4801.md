> 在面栈阅读：[Encoder-only、Decoder-only 与 Encoder-Decoder 架构有什么区别？](https://mianstack.com/question/q-4801)

## 核心回答

三种架构的关键区别是**谁能看见什么，以及输入如何交给输出**：

| 架构              | 信息流                                                                   | 常见训练目标             | 典型模型与任务                                    |
| ----------------- | ------------------------------------------------------------------------ | ------------------------ | ------------------------------------------------- |
| `Encoder-only`    | 输入 token 通常双向互相读取，得到整段输入的表示                          | 掩码语言建模等           | `BERT`；分类、抽取、检索编码                      |
| `Decoder-only`    | 在统一序列上做因果自注意力，每个位置只看自身及之前的输入                 | 下一 token 预测          | `GPT`、`Llama`、`Qwen`；续写、对话、代码          |
| `Encoder-Decoder` | Encoder 双向编码源输入；Decoder 因果读取已有目标，再用交叉注意力读源表示 | 条件序列生成、去噪重建等 | 原始`Transformer`、`T5`、`BART`；翻译、摘要、转换 |

`Decoder-only` 的目标和接口统一，容易利用海量文本训练并扩展到多种生成任务，因此在通用生成式模型中广泛采用；这不意味着另外两种架构失去价值，也不能由架构名字直接判断哪款模型质量最好。

## 用翻译任务比较一次信息流

把“我喜欢这本书”翻成英文：

1. **`Encoder-only`**：每个中文位置都可以读取全句，得到上下文化表示。接分类或抽取头很自然，但标准 `BERT` 并没有一个现成的自回归英文解码器。
2. **`Encoder-Decoder`**：Encoder 一次编码中文，Decoder 输入起始标记及已生成的英文。预测下一词时，既用因果自注意力读已有英文，也用交叉注意力选择相关中文。交叉注意力的 Q 来自解码端，K/V 来自编码器输出。
3. **`Decoder-only`**：将翻译指令、中文、回答起始标记和已有英文串成一个序列。预测下一个英文 token 时，通过同一套因果注意力读取此前输入，不需要独立的Encoder和`Cross-Attention`。

`Encoder-Decoder` 的源表示可复用，`Cross-Attention` 的源端K/V也可缓存，不是每生成一个token都重新跑一遍Encoder。`Decoder-only`则缓存统一前缀中各层K/V。

## 训练目标和掩码不能混为一谈

`BERT` 用“遮住部分词后还原”构造训练信号。被预测位置仍能读取左右两侧的其他可见词，这与生成时“未来词还不存在”的条件不同。`T5`把文本破坏后重建缺失内容，`BART`使用去噪重建；它们并非都使用完全相同的监督目标。

因果模型训练时已拿到完整参考序列，可以一次计算多个位置，再用mask阻止每个位置读取未来信息。推理时必须先确定一个输出token才能生成后一个，所以自回归生成仍逐步进行。**并行训练不等于可以越过因果约束。**

架构与目标也不是一一绑定的自然法则。表中列的是典型组合；改变mask、训练数据或输出头，会得到新的任务形式。讨论实际模型应核对其配置与训练方式。

## 怎样按任务取舍

- 需要为大量文档建立固定向量、做序列标注或分类时，先比较适配的Encoder模型：整段双向表示与任务头通常更直接。向量质量还取决于专门的表示学习训练。
- 输入输出边界清晰、重视条件转换时，`Encoder-Decoder`是一条自然路线；输入单独编码，生成端按需读取。
- 通用聊天、长任务指令、代码和工具调用需要统一生成接口时，`Decoder-only`生态成熟，易把多种任务表示为同一序列。但大模型延迟与KV开销仍需评估。

**常见追问：`Decoder-only`没有理解能力吗？** 它仍会对前缀形成上下文化表示，并能用生成方式完成分类和抽取。因果可见范围影响表示方法，不等于“只能机械续写”。反过来，Encoder也不是绝对不能生成文本，而是标准结构和目标通常不直接提供自回归生成流程。

**原始`Transformer`的Decoder和`GPT`一样吗？** 不完全一样。原始Decoder既有因果自注意力又有读取Encoder的交叉注意力；常见`Decoder-only`模型去掉了独立Encoder及这一路交叉注意力。
