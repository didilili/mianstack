## Hermes Agent（Python）

### 核心回答

`Hermes Agent` 的学习闭环是**执行任务、保留过程、筛选经验、写入记忆或技能，再在后续任务中加载使用并修订**。它改变的是运行时可用的知识与操作流程，不涉及模型参数训练。

这里有三种不同的材料：会话历史保留“当时说过什么、做过什么”，`Memory` 保留跨任务稳定的事实，`Skill` 保存一类任务的步骤、易错点和可选脚本。主 Agent 可以主动写入；满足配置的计数条件后，也可由后台复盘 Agent 检查是否值得保存。最终仍需实际调用存储工具，不能把一句“我记住了”当作已经持久化。

### 任务经验从哪里来

Agent 执行工具、收到结果和用户更正后，可以从当前上下文提取有效方法。较早的细节则由 `session_search` 回查：该版从 `SQLite FTS5` 发现相关会话，按会话沿袭根去重，但保留原始 `session_id` 与消息锚点配对，再读取附近原文或浏览近期会话。这样可以减少压缩、续接记录重复占据结果，同时保住回读原文的位置。[历史发现与沿袭去重](https://github.com/NousResearch/hermes-agent/blob/81a55437f3f31a9f12a30c53b6c5d49d420898aa/tools/session_search_tool.py#L354-L427)。

没有命中时，工具会提示 `FTS5` 默认按 `AND` 组合词项，可改用 `OR`、短语或前缀查询；检索出错或数据库不可用则返回错误，不能把它当作“没有历史”。已检索到的材料仍可能过时，需要回读上下文后判断。[数据库不可用处理](https://github.com/NousResearch/hermes-agent/blob/81a55437f3f31a9f12a30c53b6c5d49d420898aa/tools/session_search_tool.py#L601-L650)。

检索结果提供数据库中的历史材料与消息位置。历史命中也只是证据，仍需判断当时的方法是否成功、适用于什么环境，以及后来有没有被更正。把整段失败轨迹原样保存成“可靠流程”，会让下次任务重复走弯路。

### 怎样筛选并写入

系统提示引导 Agent 把可复用流程记录为技能。`skill_manage` 能创建技能、修改已有步骤和写入配套文件；已有技能只是漏了一个检查步骤时，适合修订原技能，避免每次任务再建一份近似版本。用户明确请求 `/learn` 时，也由普通 Agent 回合收集材料，再通过同一工具保存。

稳定环境事实或跨任务个人信息进入受容量限制的 `MEMORY.md`、`USER.md`；任务专属方法与偏好优先放在对应技能中。外置文件只是载体，保存动作仍可能因容量、校验或写入审批配置而失败或等待处理，应以工具结果与实际文件为准。

该版还有自动后台复盘：记忆按用户回合累计，技能按工具迭代累计，达到相应间隔且本轮正常交付后，可启动独立复盘。复盘模型读取会话快照，判断要更新什么，也可以选择没有值得保存的内容；配置可关闭自动复盘。因此它具备自动积累入口，但没有“每完成一个任务就必然生成技能”的保证。

### 后续怎样复用并继续改进

启用内置记忆时，Agent 在会话加载阶段把文件渲染为提示快照。写盘当时不会立即重刷当前系统提示；压缩边界重建提示或后续会话加载时，才重新读取这些记忆。

技能采用渐进加载：先通过名称与描述发现候选，再用 `skill_view` 读取正文，需要细节时继续读取对应参考文件。会话中新增或删除的技能，在支持该通知路径时可通过后续用户回合携带的变化说明被发现；这不要求把全部技能正文长期放进窗口。

当后续使用暴露了新限制或错误，Agent 可以再次修订技能，形成“使用、反馈、更新、再使用”的循环。闭环是否有效，要看保存内容能否被正确发现、是否减少同类错误，以及旧方法是否随环境变化得到修订；技能数量增加本身不能证明能力提升。
