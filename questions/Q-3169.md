> 在面栈阅读：[skills.md 包含哪些结构和内容？](https://mianstack.com/question/q-3169)

## 核心回答

如果题目中的 `skills.md` 指的是 **Agent Skills 的标准入口文件**，规范名称是 `SKILL.md`，放在单个技能目录根部。它由两部分组成：前面的 `YAML` 元数据描述技能名称和适用场景，后面的 `Markdown` 正文说明输入要求、执行步骤、条件分支与输出标准。脚本、参考资料和模板可以作为同目录下的可选资源。

如果团队只是把某份自定义文档命名为 `skills.md`，它的结构由团队决定；仅有这个文件名，并不能保证被支持 Agent Skills 的宿主自动发现。

## 两部分分别写什么？

| 部分   | 主要内容                                                                         | 作用                                   |
| ------ | -------------------------------------------------------------------------------- | -------------------------------------- |
| 元数据 | 必需的 `name`、`description`；按需添加 `license`、`compatibility`、`metadata` 等 | 帮助宿主识别技能，并让模型判断何时使用 |
| 正文   | 任务范围、必需输入、步骤、异常处理、资源引用、输出与验证方法                     | 技能被选中后，指导 Agent 完成任务      |

开放规范要求元数据采用 `YAML frontmatter`，正文采用 `Markdown`，并没有要求把整份技能写成 `JSON`。正文标题没有固定模板，应该围绕任务组织。

最小示例：

```markdown
---
name: sales-report
description: 根据订单明细生成月度销售报告，适用于门店月报和销售异常分析。
---

# 月度销售报告

## 输入

需要订单明细、统计月份和销售额口径。

## 步骤

1. 检查日期、金额和订单状态字段；缺少必要字段时列出缺口。
2. 读取 references/metrics.md，确认销售与退款的统计口径。
3. 调用 scripts/calculate.py 计算汇总，并核对总额。
4. 使用 assets/report-template.md 组织报告。

## 输出

交付统计范围、主要指标、异常明细与报告文件位置。
```

这里的路径展示组织方式，并不表示只写出脚本名就已经实现了计算。配套文件需要真实存在，正文应说明其输入、用法和输出。

## 辅助文件怎样拆？

```text
sales-report/
├── SKILL.md
├── references/
│   └── metrics.md
├── scripts/
│   └── calculate.py
└── assets/
    └── report-template.md
```

`references/` 放运行时需要阅读的口径和说明；`scripts/` 放可以执行的程序；`assets/` 放直接用于产物的模板、图片等资源。最小技能只有 `SKILL.md` 也可以成立，不必为了目录完整添加空文件。

`SKILL.md` 保留主流程和资源入口，长篇材料拆出去，并写明什么时候读取。这样模型先凭短描述选择技能，命中后读正文，真正需要时才读具体材料。

## 哪些字段容易混淆？

`description` 要同时讲清“做什么”和“什么时候用”，不要只写“专业助手”。`name` 按开放规范使用小写字母、数字和短横线，并与目录名一致。

`allowed-tools` 在开放规范中属于实验性可选字段，支持情况由宿主决定；`allowed_tools`、`required_context` 或任意自定义字段不能直接当成跨平台约定。即使宿主支持工具声明，真正的权限与执行限制仍由宿主和工具服务落实。

正文也不是一份项目宣传介绍。与其写“高质量生成报告”，更有用的是写清统计口径、缺字段分支、核对方式，以及什么情况下结束任务。
