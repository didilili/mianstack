> 在面栈阅读：[Agent 状态机卡死、悬停或死循环时，如何排查并熔断？](https://mianstack.com/question/q-4576)

## 核心回答

Agent 卡死时，先沿执行轨迹区分**正在等待、执行阻塞和无进展循环**，再停止失控消耗，并保留可恢复现场。界面一直转圈只是一种表象，不能据此直接重启任务。

排查先定位 `run_id` 对应的最后一个模型或工具调用，核对当前节点、等待对象、超时、最近心跳和最近有效进展。工具未返回就检查下游请求与阻塞；状态一直重复就检查路由条件、字段更新和重复调用；已经完成但界面没结束就检查终态事件及连接。

熔断由运行时执行：步数、总截止时间和费用限制兜底，无进展检测提前收敛；触发后停止新动作，传播取消，记录未完成调用和副作用。只有确认可安全重试时才从检查点恢复，结果未知的写操作先查回执。

## 按证据定位故障

| 观察到的现象                 | 优先核对                                              | 处理方向                                     |
| ---------------------------- | ----------------------------------------------------- | -------------------------------------------- |
| 已发起工具，长期没有结果     | 调用ID、下游请求状态、连接/读取超时、线程或事件循环栈 | 处理阻塞或下游故障，取消并核对真实执行结果   |
| 有心跳，一直没有新证据或产物 | 重复节点、规范化工具参数、返回结果、关键状态版本      | 检查无效重试、分页游标、退出条件与状态合并   |
| 显示等待，但没人能继续       | 等待的审批/用户/子任务ID、事件是否到达、版本是否匹配  | 修复事件关联或等待条件，设置到期处理         |
| 后端已经结束，前端仍显示运行 | 权威任务状态、终态事件、流连接和前端消费逻辑          | 修复交付链，重连后从权威状态校准             |
| Worker消失，任务一直运行     | 租约、心跳、任务队列与执行者状态                      | 确认产物和副作用后接管，拒绝旧执行者迟到提交 |

心跳只证明执行者还活着。`last_progress_at` 应对应有效证据、游标前进、待办完成或产物提交等变化；仅刷新时间戳、打印日志或换一种措辞不算任务进展。

## 怎样识别死循环？

可以记录“节点、动作、规范化参数、结果摘要和关键状态”的指纹，结合一段执行历史判断：同一搜索连续返回相同材料，或者审核反复指出同一错误而草稿没有实质变化，都是无进展信号。

指纹不能机械地只比较工具名。轮询同一个远程任务可能合理，应检查任务句柄、外部状态、查询间隔和截止时间；分页调用同一接口也正常，前提是游标和结果在推进。终止策略需要结合业务，而不是禁止重复调用。

状态字段也可能是根因。例如审核节点写了 `approved`，路由却一直读旧的 `review_result`；或者累加 `Reducer` 每次接收整份历史，让轮次、消息不断膨胀。应对照每个节点的实际输入与局部更新，确认条件边读到了预期字段。

## 熔断后怎样安全收尾？

1. **关闭新增执行**：将本次运行标记为停止中，禁止继续派发模型、工具和子任务；各层消耗计入同一根任务预算。
2. **传播取消与超时**：向支持中止的模型请求、协程、子进程和远程任务发出停止信号；不可中断的调用单独登记，不能把本地超时当作远端停止。
3. **保存现场**：记录最近检查点、已确认产物、最后错误、在途调用、幂等键和停止原因，返回已有结果及未完成项。
4. **分类恢复**：临时网络错误有限退避重试；坏参数修正后再执行；权限拒绝或确定性代码错误停止自动重试；副作用不明时先查询业务回执。

任务自身的循环预算，与依赖服务的熔断器是两个层面。某个下游连续失败时可以暂时停止访问它，并按策略降级；即使所有下游都正常，Agent仍可能在业务上兜圈子，需要任务级进展和预算控制。

## 常见追问

**调大 `recursion_limit` 能解决吗？**

它限制的是 `LangGraph` 的 super-step。应先检查状态更新和终止条件，确认任务确实需要更多步骤后再调整。它不能中断卡在单个工具内部的无限等待，也不能替代墙钟时间限制。

**恢复到上一个检查点会不会重复动作？**

可能。搜索等只读操作通常可以有限重试，创建工单、发送通知等动作应复用业务幂等键。旧Worker仍可能运行时，还需要版本或`Fencing Token`控制提交；重新运行并不等于旧运行已停止。
