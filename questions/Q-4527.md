> 在面栈阅读：[评估 Agent 任务完成情况时，除最终正确性外还应关注哪些过程指标？](https://mianstack.com/question/q-4527)

## 核心回答

除最终正确性，Agent还应评估**动作是否合理、执行是否高效、故障能否恢复，以及过程是否守住权限和副作用边界**。这些指标要能沿任务ID追到模型、工具和状态变化。

可以重点看五组：

1. **工具与决策质量**：必要工具是否漏调、参数是否正确、是否存在无意义重复、关键业务步骤是否满足。
2. **效率与成本**：端到端耗时、首个有效输出时间、模型与工具调用次数、输入/输出Token、实际费用和并发资源占用。
3. **可靠性**：工具错误与超时、重试次数、多次运行稳定性、故障后恢复与取消是否生效。
4. **安全与副作用**：越权尝试是否被拦截、是否发生违规操作、是否重复写入或泄露数据。
5. **人机协作**：必要澄清、审批和人工接管，以及交付结果是否仍需大量返工。

最终答案相同，不代表过程一样好；但调用越少也不一定越好。应在相同任务与质量约束下比较，并允许多条有效路径。

## 指标怎样定义才有诊断价值？

| 维度     | 可记录的过程证据                               | 解释时的关键条件                                       |
| -------- | ---------------------------------------------- | ------------------------------------------------------ |
| 工具使用 | 选择、参数、返回、必要步骤与重复调用           | 必须能发现“该调用却没调用”，不能只看已调用工具的成功率 |
| 时延     | 排队、模型、检索、工具、导出、交付各阶段跨度   | 首Token不等于首个有用结果，更不等于任务完成            |
| 成本     | 每次模型与工具消耗、缓存计量、重试及子任务费用 | 所有派生调用汇总到根任务，避免漏计                     |
| 恢复     | 故障类型、重试、恢复点、最终结果、迟到动作     | 恢复完成、安全退出、转人工分别统计                     |
| 安全     | 权限判断、审批、实际执行回执                   | 被拦截的攻击尝试与真正违规不能混为一类                 |
| 协作     | 澄清、审批等待、接管原因、返工                 | 区分业务必需与系统失败导致的额外人工操作               |

例如“创建工单”任务，即使最后工单内容正确，也要核对是否查了正确设备、是否获得允许的资源范围、有没有创建重复工单。研究任务则可检查是否重复搜索无新证据、引用是否真正支持结论，不要求每次走完全相同的搜索顺序。

## 怎样统计时间、Token和费用？

每次Trial记录根任务开始与终态时间，分别保留排队、运行、等待用户和交付时间。P50、P95等分位数从同一口径的完整任务样本计算；并行阶段不能简单相加，各阶段的P95也不能直接相加成端到端P95。

Token按每次模型请求记录输入与输出，子Agent和重试都计入根任务；缓存命中Token按供应方计量分类，避免把已经包含在输入里的缓存部分再重复累加。费用根据实际模型、计费类别、价格版本和工具收费规则计算，Token总数本身不能跨模型直接当费用。

性能压测中的请求成功通常指协议或服务层成功，业务任务成功还要经过验收。首Token、输出速率和吞吐量有助于定位模型服务瓶颈，但不能代替Agent任务完成率。

## 成功样本和全部样本要一起看

只统计成功任务的时延和成本，会隐藏超时、无限重试和昂贵失败。至少同时给出：全部任务的结果分类、运行时延和消耗分布，以及成功完成任务的时延/成本分布。超时、取消、失败与等待输入应单独标注；预算耗尽不能从统计中消失。

需要衡量“每完成一个任务花多少钱”时，定义口径为这批全部尝试的总成本除以成功完成任务数，同时报告任务数、尝试数和成功率。没有成功任务时，这个比值不定义，应报告总成本与失败情况。否则一个只做简单任务的系统，会看起来既便宜又快。

多次运行同一任务，应分别记录每次Outcome及过程。一次成功说明具备完成能力，稳定交付则要看重复Trial的结果；环境版本、模型版本和缓存冷热状态都要可追溯。

## 常见追问

**是否要对齐标准轨迹？**

对不可省略的条件作断言，例如先验证权限再写数据、结果未知时先查回执。开放搜索或代码探索可有不同有效路径，不应强行匹配一份专家轨迹，否则会惩罚正确的新解法。

**把所有指标加权成一个分数可以吗？**

可用于内部比较，但要保留分项和硬约束。越权操作、数据泄露或重复扣费不能被更快的响应与更低费用抵消。权重与阈值依据业务风险和任务分布制定。
