> 在面栈阅读：[Embedding 模型的原理是什么，如何训练？](https://mianstack.com/question/q-1713)

## 核心回答

检索用的 Embedding 模型把问题、句子或文档编码成可比较的向量。常见过程是：**分词得到 token → 神经网络计算上下文表示 → 池化得到定长向量 → 按模型约定进行投影或归一化**，再用余弦相似度或内积检索。

它能表达语义，来自训练目标对表示空间的塑造。检索训练通常从预训练模型出发，用“问题—相关文档”作为正样本，配合不相关或易混淆的负样本，让相关文档相对排得更高。训练更新的是编码模型的权重，文档向量是模型对文本计算出的结果。

实际训练时，重点是**样本是否符合检索任务、负样本是否可信、训练和推理编码是否一致，以及独立检索集上的效果**。并非所有 Embedding 都必须采用同一种骨干、池化或损失函数。

## 一段文本怎样变成一个向量？

以常见的文本双编码器为例：

1. **输入处理。** 使用配套 tokenizer，将文本转为 token ID，并按模型要求添加特殊 token、查询指令和长度限制。
2. **上下文编码。** `Transformer` 等骨干计算每个位置的表示。同一个词在不同上下文中可以得到不同表示。
3. **聚合与后处理。** 将多个 token 表示聚合成一个向量。可能使用均值池化、`CLS` 或末尾 token；是否加投影、是否归一化，以训练和模型接口为准。均值池化时需正确处理 padding。
4. **计算检索分数。** 文档可以提前编码，查询在请求时编码，再比较两侧向量。查询与文档可以共享参数，也可以使用经过联合训练对齐的不同编码器。

若两个非零向量是 $u=(3,4)$、$v=(0,5)$，则余弦相似度为 $20/(5\times5)=0.8$。这是向量方向的相似程度，不能解释成“文档有 80% 的概率正确”。两侧都做单位长度归一化后，内积才与余弦相似度相等。

`BERT` 可以单独编码文本；把 query 和文档拼接后共同打分，是交叉编码器的一种用法。双编码器便于复用文档向量，交叉编码器可以用于候选重排，不能说 `BERT` 天生只能拼接两段文本。

## 如何组织训练？

**先确定任务，再准备正负样本。** 例如“手机遗失后怎样冻结账户”的正样本应包含冻结账户的办理方法，而不只是另一句主题相近的问法。可将数据组织为查询、一个或多个相关文档，以及可选的负文档；去除泄漏、重复和错误配对，并保留适用时间、版本等条件。

从适合语言和领域的预训练模型开始，配置与模型匹配的池化、相似度和训练目标。现代检索模型常使用对比学习。对查询 $q_i$、正文档 $d_i^+$ 和包含正例及负例的候选集合 $C_i$，一种常见损失是：

$$
L_i=-\log\frac{\exp(s(q_i,d_i^+)/\tau)}{\sum_{d\in C_i}\exp(s(q_i,d)/\tau)}
$$

$s$ 是相似度，$\tau>0$ 是温度。它将“在候选集合中选出正例”作为分类目标，反向传播更新编码器及其他可训练参数。候选、标注等条件固定时，提高正例相对负例的分数会降低损失；这不意味着任意两篇相关文档都要无条件靠到同一点。

`MultipleNegativesRankingLoss` 是这类目标的常见实现：其他样本的正例可充当当前查询的批内负例，也可提供显式负例。除对比目标外，原始 `Sentence-BERT` 还讨论了自然语言推断分类、相似度回归和三元组损失；要按监督数据和任务选择，不能把某个损失当成全部 Embedding 模型的定义。

## 负样本为什么经常决定效果？

- **随机负例**容易取得，但可能过于简单，也可能意外包含相关文档。
- **批内负例**能利用同一批次的其他文档，但“属于别的查询”不等于“对当前查询不相关”。同义问题和共享答案容易产生假负例。
- **难负例**可以从关键词检索或当前向量检索的高排名结果中挖掘，要求它看起来相近、却不能回答该问题。例如同名产品的旧版流程，需要结合问题的版本条件判断。

先检查是否存在多个有效正例、重复片段或标注遗漏，再决定过滤、改为多正例训练或复核样本。只去除完全重复的文本，无法消除所有语义上的假负例。负例也不是越难越好，错标的“难负例”会直接把模型往错误方向训练。

## 怎样确认训练有效？

按文档来源、业务实体或近重复组隔离训练集与测试集，避免同一内容换个问法就进入测试。固定语料、切块和检索配置，比较训练前后的 `Recall@K`、`MRR`、`nDCG`，同时看领域、跨语言、精确编号等分组和编码成本。训练损失下降、句子相似度分数提高，都不能代替实际检索验证。

上线时保持 tokenizer、查询指令、池化、归一化和相似度约定一致。更新模型后，即使向量维度相同，也不能假定兼容旧文档向量；通常需要重算文档表示并验证新索引。

若追问传统词向量，`Word2Vec` 的 `CBOW` 用上下文预测中心词，`Skip-gram` 用中心词预测上下文。它们学习词级表示；面向整段文本检索时，还需要说明上下文编码、聚合方式及检索监督，不能只回答一次词表查找。
