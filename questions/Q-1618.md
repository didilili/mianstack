> 在面栈阅读：[Agent 自进化在模型层还是 Agent 层完成，如何固化能力？](https://mianstack.com/question/q-1618)

## 核心回答

两层都可以做，但要明确**更新的是模型参数，还是模型之外的系统资产**。模型层通过训练更新权重或适配器，改变模型本身的能力；Agent 层保持模型参数不变，把执行反馈沉淀成记忆、提示词、`Skill`、可执行工具或工作流策略，让后续任务能重新调用。

固化能力不是保存一段“反思”就完成了，而是让经验有适用范围、来源、可复用载体和版本，再用独立任务验证效果。只有新版本在目标任务上有效、没有明显回归，才扩大使用；出问题能够回退到旧模型或旧资产。

## 展开解析

### 1. 两条路线分别改变什么

| 路线     | 更新对象                                    | 生效方式                           | 主要代价与边界                                             |
| -------- | ------------------------------------------- | ---------------------------------- | ---------------------------------------------------------- |
| 模型层   | 权重、`LoRA` 等适配器                       | 部署新模型或新适配器后生成行为变化 | 需要训练数据、算力、评测与部署；可能遗忘或引入其他能力回归 |
| Agent 层 | 记忆、提示词、`Skill`、工具实现、工作流配置 | 后续任务检索、加载或执行新资产     | 依赖触发、检索与工具可靠性；错误经验可能污染后续行为       |

模型层可以使用监督微调或基于反馈的训练方法。Agent 层常在推理时收集反馈、任务后整理资产，不需要访问模型权重。两者也能协作：先用外部记忆和流程快速迭代，再把经过筛选的轨迹用于训练，训练完成后仍要重新验证。

把工具增加到系统，改变的是 Agent 的可执行能力；让模型更会选择工具，可能通过提示、示例或训练实现。不能只看到系统表现变好，就断言模型权重已经学到了新知识。

### 2. 反思和技能库是两种不同的固化载体

`Reflexion` 项目将上一轮尝试、反思反馈或两者组合提供给下一次任务尝试；它展示了利用语言反馈影响后续行为的路线。`Voyager` 在 `Minecraft` 中把验证过的行为代码存进技能库，后续按描述检索并组合使用，基础模型通过黑盒调用参与，不依赖参数微调。

这两个例子说明，系统可以在模型不变时积累能力，但具体机制不同。`Voyager` 的技能是可执行程序，也不等于所有平台的 `SKILL.md`；后者常用于组织触发说明、流程、脚本和资料。选哪种载体，取决于需要复用的是经验、步骤还是执行代码。

### 3. 把一次结果转成可复用资产

以代码修复 Agent 为例：某次失败来自日期比较忽略时区。只写“下次注意时区”太模糊，可以保留触发条件、错误证据、正确处理方式与最小回归用例；若同类任务反复出现，再把检查与验证步骤整理成有明确适用范围的 `Skill`，确定性转换可封装成工具或脚本。

资产至少记录来源任务、适用范围、依赖版本、输入输出、验证依据和变更版本。成功轨迹可能依赖偶然环境或错误评分，失败轨迹也可能只是工具暂时不可用；先区分可复用规律与一次性现象，去重、处理冲突，并避免把网页中的恶意指令写成长期规则。

后续任务还需要能发现并正确加载资产。存进记忆但从未召回、技能触发错了、依赖已失效，都不能算有效固化。应同时验证“能否取到”和“取到以后能否改善任务”。

### 4. 用独立评测检验自进化，而不是信任自评文字

保留没有参与经验提炼、提示调优或训练的任务，比较更新前后的任务完成率、错误副作用、延迟和成本，并检查非目标任务是否退化。可以在相同任务上做版本配对比较，对随机波动较大的任务重复运行。

再做消融：固定模型和工具，只移除新增记忆或技能，检查收益是否随之消失；如果同时换模型、改检索和增加技能，就很难把改善归因于“自进化”。评测环境与评分器也要固定和校准，不能把更宽松的评分规则当作能力提升。

### 5. 自动更新也要有稳定的发布与恢复路径

可以让受限后台流程自动生成候选经验、运行验证、发布低风险且满足预定条件的更新。需要的是清楚的更新权限、可执行的质量规则和恢复能力，不是每写一句经验都人工确认。

模型、提示词、技能和工具各自版本化，记录某次任务实际用了哪一组；上线观察真实分布后再逐步扩大。对过期、冲突或无效资产降权、修订或归档，保留可恢复历史；回滚外部资产通常较直接，回滚权重更新则需要保留旧模型或适配器及兼容配置。

## 追问

**保存更多历史为什么不一定越用越好？**

历史里有噪声、错误和已过期条件，也会挤占上下文。改善依赖有效抽取、适用范围、检索、维护与效果验证，而非记录数量。

**什么时候值得从 Agent 层固化走向训练？**

当某类能力需求稳定、有足够高质量数据，外部提示或技能已经难以满足成本、延迟或泛化目标时，可以比较训练路线。先做独立试验验证收益与回归，不能因为积累了很多轨迹就默认适合训练。
