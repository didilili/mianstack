## 核心回答

Git负责在本地记录提交、分支、合并和历史；GitHub、码云等平台提供远程托管，以及PR/MR、评审、Issue、权限与CI协作。通常围绕一次明确改动整理提交，在团队约定的分支上开发，验证后推送并发起评审，合并后同步主分支。

回答“是否使用过”时，可接着说明实际参与的环节，例如是否解决过冲突、做过评审或维护过流水线；不需要把没有参与的团队流程说成个人经历。

## 一次改动如何管理

修改前先确认当前仓库、分支和已有工作，开发中用状态与差异检查区分工作区、暂存区和提交。提交前只纳入本次改动，检查测试、配置与敏感文件，写清改动目的。commit只保存本地历史，push才把提交发送到指定远程分支。

协作前先获取远程更新，理解目标分支已有变化，再按团队习惯合并或变基。fetch更新远程跟踪信息，不直接替当前分支完成合并；pull则包含获取和后续集成，需要知道当前策略。

## 冲突与回退

冲突时对照共同基线及双方意图编辑结果，去掉冲突标记后检查最终行为并完成合并；不能机械“全选自己”或“全选对方”。合并后没有冲突也仍可能有语义问题，应验证相关功能。

已共享历史上的错误通常通过新的反向提交修复，保留协作记录；本地尚未共享的历史整理可以更灵活。重写别人正在使用的历史会影响其分支，团队应提前约定。

## 追问

远程仓库是重要备份与协作入口，但本地未提交或未推送的内容不一定已被保存到远端。版本管理是否完成，应区分文件已改、已提交、已推送、已合并与已发布。

## 参考资料

- 国内：[廖雪峰：解决冲突](https://liaoxuefeng.com/books/git/branch/merge/index.html)：冲突场景说明合并不仅是保留某一边，还要理解双方修改的最终语义。
- 国内：[廖雪峰：多人协作](https://liaoxuefeng.com/books/git/branch/collaboration/index.html)：借鉴本地与远程分支的协作流程，解释正文中本地提交历史和向远程共享提交的区别。
- 国内：[廖雪峰：添加远程库](https://liaoxuefeng.com/books/git/remote/add-remote/index.html)：本地仓库关联远程的例子说明Git与托管平台分别承担什么职责。
- 国外：[Pro Git / Scott Chacon、Ben Straub：Basic Branching and Merging](https://git-scm.com/book/en/v2/Git-Branching-Basic-Branching-and-Merging)：提交图上的分叉与合并解释分支协作怎样保留开发历史。
- 国外：[Pro Git / Scott Chacon、Ben Straub：Working with Remotes](https://git-scm.com/book/en/v2/Git-Basics-Working-with-Remotes)：获取远程记录和推送提交的区别说明本地保存与远端共享是不同阶段。
