## 核心回答

Agent 任务规划，是把用户目标转成可执行、可检查，并能随反馈调整的行动安排，主要包含五项内容：

1. **明确目标和约束**：要交付什么，范围、时间和资源限制是什么，怎样算完成。
2. **拆分子任务**：把大目标拆成有明确输入、输出和完成标准的小目标。
3. **安排依赖与顺序**：哪些步骤需要前置结果，哪些可以独立进行，下一步先做什么。
4. **选择执行方式**：给子任务匹配工具或执行者，考虑所需信息、权限和预算。
5. **根据反馈维护计划**：记录实际进度，检查结果；遇到信息缺口、失败或目标变化时调整后续步骤，完成或达到边界时结束。

例如写一份研究报告，可以先确定研究范围，再搜集资料、比较分析、补齐证据，最后生成并检查报告。若发现资料不足，就补查相关部分，而不是无论结果如何都机械执行最初的清单。

## 展开说明

### 1. 先把“做完”说清楚，再拆步骤

同样是“调研某项技术”，可能只需要简短说明，也可能需要带来源的比较报告。规划前应明确输出形式、研究范围、资料时效和评价维度。关键条件缺失、会明显改变行动时，先澄清；已有足够信息则直接推进，不必为每个细节额外确认。

分解后的子任务应能判断完成情况。例如“搜集资料”太宽泛，可以进一步明确要查什么问题、得到什么证据，以及保存在哪里。粒度以能够执行和验证为宜：太粗容易遗漏工作，太细则增加调度和维护成本。初始信息不足时，可以先确定阶段目标，执行中再细化。

### 2. 计划要说明依赖，执行要返回真实结果

规划器的输入可以包括用户目标、当前状态、已知事实、可用工具和剩余预算；输出是子目标、执行顺序或依赖、预期产物及完成条件。它可以是一段提示和结构化输出，也可以是独立节点，是否拆成单独模块取决于复用、复杂度和测试需要。

执行层根据计划选择当前可执行的步骤，调用工具或委派任务，回传状态、产物引用和错误。依赖前一步结论的任务需要等待；输入已经齐备且相互独立的任务可以并行，也要考虑资源和共享状态是否允许。

**计划中的“已完成”必须有执行依据。** 写出“查询数据库”不代表已经查询，把待办标成完成也不代表结果符合要求。需要以实际工具结果、生成的产物和必要检查更新进度。计划用于指导执行，任务状态用于记录已经发生的事实，两者应保持一致。

### 3. 重规划针对变化，不是每一步都推倒重来

工具反馈可能表明原假设不成立、关键数据缺失或某项能力不可用。此时可以修改受影响的步骤、改用可用来源，或说明无法完成的部分。已经验证且仍然有效的结果可继续使用；若研究范围变化导致旧结果不再适用，则需要重新处理相关部分。

短暂网络失败可能只需有限重试，不必重新生成全部计划；反复搜索没有新增证据，则应改变检索方向或停止，而不是不断增加待办。计划还应遵循总时限、调用次数或费用预算。达到限制时，交付已有结果和缺口，或保存进度等待补充条件，不能用重规划重置消耗。

对会修改外部系统的步骤，要另外确认执行状态和所需授权。计划更新不会自动撤销已经发生的操作，也不意味着原来的授权覆盖新增动作；发生超时且结果未知时，应先核对外部状态，再决定后续步骤。

### 4. 用研搜任务串起规划内容

以研搜教程为参考，假设用户要求“比较两项技术，并结合内部资料给出报告”：

- **目标**：交付有来源的比较报告，先确定比较维度和资料范围。
- **分解与依赖**：分别收集两项技术的外部资料；按问题查内部知识库；材料齐备后比较，最后生成报告。具备独立输入的收集任务可以并行。
- **执行分工**：网络助手负责外部搜索，知识库助手负责内部资料，主 Agent 组织结论和报告；只有确实需要业务数据库信息时才增加相应查询。
- **反馈调整**：某个维度没有可靠证据，就补查该项；内部资料与外部资料冲突，则核对时间、版本和适用条件，并保留差异。
- **完成判断**：报告覆盖约定维度、关键结论有依据，未解决问题明确说明，生成的文件可以读取。

这是将参考项目能力组织成计划的示例。实际任务不需要因为配置了多个助手，就把每个助手都调用一次。

## 常见追问

### 规划一定要先输出一份完整计划吗？

不一定。简单查询可以直接选择工具；开放任务也可能边执行边细化。任务较长、依赖较多或需要展示进度时，显式计划更有用。Plan-and-Execute 可以承担整体安排，局部步骤仍用 ReAct 根据观察决定下一动作，两者可以组合。

### 任务规划等于使用某个产品的 Plan Mode 吗？

不等于。任务规划是系统能力，产品中的 Plan Mode 是一种具体交互或运行模式。判断是否具备规划，应看目标怎样分解、步骤怎样执行和反馈怎样改变计划，而不是只看界面名称。

### 用待办工具以后，还需要自己实现什么？

待办工具通常帮助模型维护任务条目和状态。比如当前 Deep Agents 从 v0.7 起需要显式配置规划中间件，以提供 `write_todos`。真实工具执行、前置依赖、预算、结果校验和失败处理仍需由执行系统及业务逻辑承担，不能把一份清单当成完整调度器。
