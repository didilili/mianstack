## 核心回答

联表按关联键组合数据，分页限制一次返回的记录，聚合函数按分组汇总，索引则帮助减少过滤、连接和排序的访问成本。写`SQL`先明确结果的一行代表什么，再选择`JOIN`、`GROUP BY`和稳定排序，避免联表放大行数后把统计或分页算错。

## 联表与聚合例子

假设用户表`users`含`id`和`name`，订单表`orders`含`id`、`user_id`和`amount`。下列查询保留没有订单的用户，统计订单数和总额：

```sql
SELECT u.id, u.name, COUNT(o.id) AS order_count,
       COALESCE(SUM(o.amount), 0) AS total_amount
FROM users AS u
LEFT JOIN orders AS o ON o.user_id = u.id
GROUP BY u.id, u.name
ORDER BY u.id;
```

`LEFT JOIN`保留左表，未匹配右表列为`NULL`；因此统计订单用`COUNT(o.id)`，不能用`COUNT(*)`把无订单用户也计作一单。`WHERE`在分组前过滤行，`HAVING`过滤聚合后的组；给右表条件放到`WHERE`时，还要检查是否意外排除了未匹配用户。

## 分页与索引

分页要有确定顺序。若创建时间可能相同，增加唯一ID作为第二排序键：

```sql
SELECT id, user_id, amount
FROM orders
ORDER BY created_at DESC, id DESC
LIMIT 2;
```

深`OFFSET`仍需跳过很多记录，连续浏览更适合基于上一页排序键的游标。联表前后的分页粒度要一致，例如按订单分页时，不应先与订单明细展开后直接限制明细行数。

`orders.user_id`上的合适索引可帮助按用户关联，过滤和排序的联合索引要按实际查询设计。最终用执行计划核对访问顺序、扫描与排序；`GROUP BY`并不保证输出顺序，想排序应明确`ORDER BY`。
